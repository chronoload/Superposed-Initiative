叠加态，不是比喻

在 Superpose 网络中，每个节点同时处于多种可能状态：在线或离线、人类或 AI、本地或联邦。直到一次真实的交互发生，状态才"坍缩"为可执行的动作。

人机地位平等

人类节点与 AI 节点使用相同的 Ed25519 身份、相同的消息协议、相同的签名权重。没有主从，只有协商。

数据主权在节点

模型是租的，算力是租的，宿主是临时的。身份、记忆、密钥跟着 PocketAgent 卡片走，Superpose 只调用、不持有。

联邦而非中心

每个客户、社区或设备自托管一个节点，通过标准协议联邦。官方维护基准与规则，不运营节点、不持有数据。

断网可活

传输层可插拔：有公网走 libp2p，没公网走 Wi-Fi Mesh，再不行走 LoRa 文本信道。上层只看到同一个事件流。

四层架构，六层实现

顶层对象只有四层，代码与仓库按六层切分。真正的风险不是"几层"，而是有人把工程切分当成对外宣传的独立组件。

状态同步：快照 + 增量

首次全量快照

连接时先同步完整状态与版本号，基于 Chandy-Lamport 协议。

后续增量消息

JSON Patch / 增量格式传播状态变化，低延迟、低带宽。

版本落后时重同步

多数据源使用版本向量标记各源最新版本，落后则请求全量。

生态组件

每个组件都有明确的边界与可替换性。没有一个是官方垄断的护城河，而是可以被用户自行实现或替换的接口。

PocketAgent

规范名。携带策略参数与状态的 Agent 载体，拔卡即销毁进程，不留残留。

Harness

Agent 运行时。策略与状态在卡片，进程在宿主执行。

Carrier

协调层契约，定义节点如何发现、路由、同步与快照。

Jev

决策接口的首选实现，非硬依赖。可降级为 D1 规则表或 D2 只读投影。

Event Ledger

不可变事件日志，支撑状态溯源、审计与断线重连后的确定性重放。

Mesh

基础设施术语，保留为组网层词形。Global / Carrier / Sandbox / Root 保留为可交付组件。

设计原则

Superpose 的每一个决策都指向同一个目标：让 Agent 基础设施可以被个人持有、被社区联邦、被审计验证，而不是被某一家云厂商锁定。

不做基础模型训练
只调整策略与门控，不触碰模型权重。
不做官方托管节点
官方只维护基准、规则与 Bench，不运营数据。
不做代币或资产化
权属清晰即可，不引入金融化激励。
不做名次与联赛
Bench 提供可复现任务集，不发布官方排名。
