# Superpose

> 组网分布式系统与主体化终端系统。**Protocol 是第一等公民**：它规定设备如何组网、什么信息合法、权限如何校验、运行态如何坍缩。全局状态量子与 Protocol 同地位，是组网内部的全局实时路由广播信息流。Mobile Suite 是 Protocol 在终端侧的接口实现，从 Harness 发展而来，**与 Agent Core 完全解耦**。Embody 是 Protocol、Mobile Suite、Agent Core 三源汇合形成的运行时；**Embody 在哪个设备实例化，不等于它拥有哪个设备的运行所有权**——它能调用的是组网内全部有权限可执行的行为。Agent Core 是物理载体，像户籍一样承载身份、记忆、授权与责任。**模型的强大不可怕，可怕的是强大而没有锁；Superpose 把 agent 的倾向、边界与责任锁定在系统中，而不是只寄希望于模型自我对齐。** 模型是耗材，Agent Core 是你的。

## 这个项目解决什么问题

今天的 agent 产品看起来很热闹，但落到真实系统里，痛点很具体：

- **大多只能在一个设备工作。** 换一台机器，身份、记忆、会话上下文就断了，agent 被锁在单设备里。
- **会话全托管在云。** 身份、记忆、会话历史不属于用户，换服务商或断网就不可用，数据主权不在自己手里。
- **对系统状态无知。** agent 只能靠工具返回的局部观察，不知道全局环境、权限分布、其他设备状态，介入不了系统拓扑。
- **延迟较高。** 每次操作都要网络往返，没法实时持续运行，做不了需要快速反应或长期驻留的任务。
- **训练只有项目信号，没有系统控制信号。** 现有训练多围绕任务完成，缺少对权限、环境、跨设备操作、系统控制这类信号的建模。
- **Harness 会话间丢失配置上下文。** 每个会话重新配置，上下文不连续，工具、权限、记忆管理混乱。
- **权限一大堆，需要人不停点各种确认按钮。** 权限模型碎片化，缺少统一身份与授权层。
- **agent 被当成“工具”，没有身份户籍。** 权限只有“准/不准”二元开关，没有等级、没有来源、没有责任主体；出了事无法追溯，也无法与人类操作者等价共存。
- **模型越强，失控风险越大，但安全只寄希望于模型自我对齐。** 模型商把模型训练得强大而“无害”，可一旦接入真实系统、拥有真实权限，仅靠对齐训练无法保证行为边界；缺少架构级的锁定、追溯、撤销与退相干机制。**防止智械危机不能只靠模型侧，必须在系统架构层锁定所有倾向。**

Superpose 要解决的就是这些：让 agent 不再是一个被云托管的单设备会话，而是一个**可携带、可实例化、能感知系统状态、在终端持续运行、身份与权限统一、有户籍、有责任主体、能与人类等价操作设备、且行为边界被系统架构锁定**的系统实体。模型参数与算力全部外包给模型提供商；本侧只保留 Protocol、全局状态量子、Embody、Mobile Suite、Agent Core 与 Valid Space。**模型是租的，Agent Core 是你的。**

核心判据只有一句：**只有形成组网式模型能力，才谈得上下一代智能系统。** 单点模型再强，如果介入不了系统拓扑、会话托管在云、对系统状态无知，它就仍然是旁观者；如果没有架构级的行为锁定，它就越强越危险。

## 调研与差异化

在把 Superpose 写成 SPEC 之前，我们系统梳理了同方向的产品与方案。结论是：**问题诊断已经趋同，运行态契约与架构级安全锁定还没有。**

| 方案 | 它做了什么 | 它停在哪 |
|---|---|---|
| IUAA（2026.03） | 密码学戒指锚定身份与加密记忆；推理外包；跨设备调用轻量 agent | agent 是 stateless 查询路由，没有持续运行态；没有内建的系统状态感知；没有退相干生命周期；没有户籍式身份；没有架构级行为锁定 |
| 可悠 Care U | 同一 agent 的上下文与记忆在家庭、车载、办公设备间同步 | 依赖厂商云端协同中枢，身份与记忆仍锚定在平台侧 |
| Violoop | 巴掌大硬件连接 PC，本地小模型理解屏幕，本地图数据库存长期记忆 | 单机增强场景，没有扩展到跨设备组网与系统状态感知 |
| 荣耀 Agentic OS | 系统级 Agent Harness；一脑调度万端，多设备多 Agent 协同 | 绑定荣耀生态账户体系，不是可拔插、跨生态携带的 Agent Core；agent 仍是工具，不是户籍主体 |
| TopoClaw | 设备拓扑与社交拓扑耦合；跨设备动作放置；跨用户身份归因 | OS 层参考架构，没有“物理载体携带记忆与身份”这一层 |
| Nexus | agent 推理与环境执行分离；agent 路由协议；run-scoped delegation | 重心是执行路由与生命周期管理，不是身份与记忆的物理主权 |
| 阿里云 / AWS AgentCore | 云端企业级 agent 托管与治理 | 方向相反：把 agent 稳定跑在云上，而不是把身份与记忆拿回物理载体；安全靠云侧策略，不是架构级物理锁定 |
| Meta Muse / OpenAI dots / OpenClaw | 持续运行的个人 agent，记忆与会话跨会话保持 | 云端托管，平台锁定没有被打破；安全依赖模型对齐 |

这些方案共同确认了三件事：身份与记忆必须脱离平台；物理载体是可行的锚点；模型推理可以稳定外包。**它们没有共同解决的是运行态、社会性、身份户籍与架构级安全**：

- agent 是临时被调用的推理请求，还是在终端持续运行的具身 loop；
- agent 对宿主系统的状态有没有内建的、协议级的感知；
- 拔掉载体之后，运行态算什么——终止、暂停，还是退相干；
- 权限是密钥持有即身份，还是可验证的三层身份 + 双要素授权；
- agent 在哪个设备实例化，是否等于它拥有哪个设备的运行所有权；
- agent 与人类是否能在同一套权限体系中等价操作设备；
- agent 有没有户籍、有没有责任主体、能不能形成网内社会；
- **模型越强，行为边界靠什么锁定——只靠模型对齐，还是靠系统架构**。

Superpose 的创新点，就是在这八个问题上给出可验收的契约。

## 核心概念（按依赖顺序）

这一节从 Protocol 开始，按依赖顺序解释 Superpose 的核心概念。**Protocol 是根，全局状态量子是 Protocol 组网的信息流，Mobile Suite 是 Protocol 在终端的接口实现，Embody 是三者汇合的运行时，Agent Core 是这一切的物理锚点与户籍载体，而架构级安全锁定贯穿所有层。**

### 1. Protocol：Superpose 的第一等公民

**一句话：Protocol 不是消息格式约定，它是 Superpose 的系统宪法。**

在大多数 agent 框架里，“协议”是附属品：先有框架，再定义消息怎么传。Superpose 反过来：**Protocol 是第一等公民，系统是 Protocol 的实现。** 它规定的不只是“消息长什么样”，而是四件事：

1. **设备如何组网**：Mobile Suite、全局状态量子、Agent Core 之间的唯一通信标准；全集/子集结构；节点抽象由 Mobile Suite 承担。
2. **什么信息合法**：合法信息判定规则框架；子集声明并解析合法性结构字段；只有合法信息构成 Valid Space 元素。
3. **权限如何校验**：Mobile Suite 处理远程请求时，如何从全局状态量子获取权限信息；验签 + 本地策略比对的双校验规则；兼容签名方向。
4. **运行态如何坍缩**：agent 进行时如何由可解读子集与当前 loop 状态形成；退相干如何生效；会话信息如何留存。

**为什么 Protocol 必须是第一等公民：**

- **没有 Protocol，组网就是私有接口的堆叠。** 每个设备、每个应用各自适配，回到“Harness 会话间丢失配置”的老问题。
- **没有 Protocol，合法信息无法判定。** 什么能进 Valid Space、什么不能，没有统一规则；全局状态量子就退化成不可信的数据池。
- **没有 Protocol，权限校验没有共同语言。** 每个 Mobile Suite 各自解释权限，碎片化授权无法收敛。
- **没有 Protocol，坍缩和投影讲不清楚。** agent 进行时从哪来、退相干后算什么，没有可验收的契约。
- **没有 Protocol，安全边界无法锁定。** 行为边界必须由协议规定、由所有节点共同执行，而不是靠每个模型自己“想不想遵守”。

**Protocol 的结构：全集 / 子集。**

- **全集**是社区/官方维护的版本化事实标准，包含所有可选组件、消息类型、规则与扩展点；个人/组织可衍生定制，但衍生版本不得自称事实标准全集。
- **子集**是终端 Mobile Suite 或 Agent Core 实际实现的部分；必须声明基线版本、裁剪项、合法性结构字段；不同终端子集可不同；异构设备——Linux、Android、鸿蒙、嵌入式——通过子集接入同一张网。

**Protocol 与其他概念的关系：**

- **与全局状态量子同地位**：Protocol 定规则，全局状态量子定实时状态流。规则 + 状态流，才构成可坍缩、可投影的组网。
- **与 Mobile Suite 是“规定与执行”的关系**：Protocol 规定通信标准、合法信息判定、权限校验规则；Mobile Suite 是这些规则在终端侧的接口实现与节点抽象承担者。Mobile Suite 不定义协议，它执行协议。
- **与 Embody 是“产生条件与运行时”的关系**：Protocol 产生全局状态量子，Embody 从全局状态量子中解出可解读子集并坍缩为 agent 进行时。
- **与 Agent Core 是“校验与被校验”的关系**：Protocol 规定兼容签名机制，Agent Core 单向验证 Mobile Suite 签名；Protocol 规定权限校验规则，Agent Core 与 Mobile Suite 按规则交互。

**Protocol 不是什么：**

- 不是中心内核。不存在运行时中心决策者；Protocol 全集是规范，不是运行时中心。
- 不是固定载荷格式。Protocol 不规定具体传什么；具体传输由 Embody 实现，隔离上下文正文是推荐实践，不是协议强制。
- 不是可被私有协议替代的“建议”。唯一通信标准由 Protocol 规定；不得使用私有通信协议替代。

### 2. 全局状态量子：Protocol 组网内部的全局实时路由广播信息流

**一句话：全局状态量子是 Protocol 组网内部的全局实时路由广播信息流，与 Protocol 同地位。**

它不是一个被动的状态存储，不是“数据库里的全局快照”，也不是“每个终端轮询拉取的配置”。它是组网内部持续流动的信息流：每个实例化终端都在广播自己可公开的环境状态、权限与操作抽象、动态设备状态、接口元数据；这些广播在 Protocol 规定的通信标准下汇聚成一份全局实时视图，再分发给所有实例化终端。

**为什么它与 Protocol 同地位：**

- **Protocol 规定“什么信息合法、怎么通信”**；全局状态量子是“合法信息在组网内的实时流动形态”。没有 Protocol，信息没有合法性；没有全局状态量子，合法性没有实时载体。
- **坍缩依赖它**：agent 进行时是终端从全局状态量子中解出可解读子集、再与当前 loop 状态坍缩的结果。没有全局状态量子，坍缩没有输入。
- **投影依赖它**：agent 对系统状态的感知不是靠工具碎片拼凑，而是靠全局状态量子持续投影到终端。没有它，“对系统状态无知”的问题无解。
- **路由依赖它**：跨设备操控、远程 Embody 请求、权限校验，都需要知道“目标设备当前状态、权限分布、接口可达性”。这些信息由全局状态量子实时广播。
- **组网级权限依赖它**：agent 能调用什么，不取决于它在哪个设备实例化，而取决于全局状态量子中记录的权限分布。**Embody 在 A 设备实例化，不代表它只能操作 A 设备；它能调用的是组网内全部有权限可执行的行为。**
- **安全锁定依赖它**：行为边界、权限分布、责任归属都编码在全局状态量子中；agent 不能绕过它自行解释权限。

**它和 Valid Space 的关系：** Valid Space 是合法信息构成的数学空间；全局状态量子是 Valid Space 中的一个点。状态属于量子，不是“写入空间”。

**终端如何读取它：** 终端只能解出**可解读子集**，由密钥、权限、Mobile Suite 适配共同决定。不同终端可解读子集可不同。Agent Core 可向全局状态量子**单向贡献**授权公开信息，贡献须双判；主体化数据、大脑记忆、上下文正文永不出 Agent Core。

### 3. Mobile Suite：Protocol 在终端侧的接口实现，Harness 的系统化演进，与 Agent Core 完全解耦

**一句话：Mobile Suite 是 Harness 的系统化、协议化、跨会话化演进，是 Protocol 在终端侧的接口实现与节点抽象承担者；它和 Agent Core 完全解耦。**

先看 Harness 是什么。今天的 Harness（LangChain、AutoGen、Cursor 的 agent 层等）本质上是**应用层的胶水**：它在单个设备、单个会话内，把模型调用、工具调用、上下文拼接、权限确认串起来。它的局限正是痛点清单里的那几条：

- 会话间丢失配置：每个会话重新装配工具和权限；
- 单设备绑定：换设备就要重装、重配；
- 权限碎片化：每个应用各自弹确认；
- 不感知系统状态：只知道工具返回了什么。

Mobile Suite 是从 Harness 往前走的下一步：

| 维度 | Harness | Mobile Suite |
|---|---|---|
| 层级 | 应用层胶水 | 系统级接口中间层 |
| 范围 | 单设备、单会话 | 跨设备、跨会话 |
| 通信 | 各应用私有接口 | Protocol 规定的唯一通信标准 |
| 权限 | 应用各自弹确认 | 协议级双校验（验签 + 本地策略） |
| 状态感知 | 工具返回的局部观察 | 通过全局状态量子获取系统状态 |
| 与 agent 的关系 | 承载 agent loop | 不承载 loop；只提供接口与校验 |
| 节点抽象 | 无 | 承担组网节点抽象，替代 Carrier |
| 与 Agent Core 关系 | 通常绑定 | **完全解耦** |
| 安全角色 | 无系统级安全边界 | **协议级安全边界执行者**：权限校验、请求日志、兼容签名验证 |

**Mobile Suite 和 Agent Core 的解耦：**

- **Mobile Suite 是系统级、跨 agent 的**：它由终端 OS 按 Protocol 规范预装/热更新，不隶属任何单个 Agent Core。一台设备上的 Mobile Suite 服务所有插入该设备的 Agent Core。
- **Agent Core 是单 agent 的**：它承载一个 agent 的身份、主体化数据、会话信息；它不依赖特定设备的 Mobile Suite，也不拥有特定设备的运行所有权。
- **插入任意设备即可工作**：Agent Core 插入任何有合规 Mobile Suite 的设备，都能通过 Protocol 完成鉴权、三源汇合、Embody 实例化；换设备不需要重新配置 Mobile Suite。
- **Mobile Suite 不因某个 Agent Core 离开而消失**：移除 Agent Core 后，Mobile Suite 仍在终端可用；它继续服务下一个插入的 Agent Core。
- **Agent Core 不因更换设备而失去身份**：Agent Core 在 A 设备实例化，换到 B 设备仍能实例化；它的身份、记忆、会话信息随 Agent Core 走，不随设备走。

**Mobile Suite 和 Protocol 的关系**：Protocol 规定通信标准、合法信息判定、权限校验规则；Mobile Suite 是这些规则在终端侧的**接口实现与节点抽象承担者**。它不定义协议，它执行协议。

**Mobile Suite 和 Harness 的不同**：Harness 是“为一个 agent 会话服务的胶水”；Mobile Suite 是“为所有 agent 实例提供统一接口的系统中间层”。Harness 随应用走，Mobile Suite 随终端 OS 走；Harness 管会话，Mobile Suite 管接口、权限校验与请求日志。**Superpose 不是不要 Harness，而是把 Harness 里“系统级、跨会话、协议化、安全边界执行”的那部分抽出来，沉淀成 Mobile Suite。**

### 4. Embody：三源汇合的运行时，实例化位置不等于运行所有权

**一句话：Embody 是 Protocol、Mobile Suite、Agent Core 同时作用的结果，是 agent 的运行时；Embody 在哪个设备实例化，不等于它拥有哪个设备的运行所有权。**

它不是 Agent Core 本身，不是 Mobile Suite 本身，也不是 Protocol 本身。它是三源在终端实例化时汇合的产物：

- **Agent Core** 提供身份、主体化数据、会话信息、Embody 运行时、Protocol 终端实现；
- **全局状态量子**（由 Protocol 组网产生）提供系统环境、权限与操作抽象、动态设备状态；
- **Mobile Suite** 提供设备自身接口信息。

三源汇合，Embody 才形成；缺任一源，实例化失败或降级。

**Embody 和 agent loop 的相似性**：Embody 是运行时，agent loop 是运行时的核心循环。两者都是“感知—决策—行动”的循环。Embody 的感知来自全局状态量子的可解读子集 + Mobile Suite 的设备接口信息 + Agent Core 的会话信息；决策由终端侧 loop 完成，模型只提供推理；行动通过 Mobile Suite 落到设备。

**实例化位置与运行所有权的分离：**

- **Embody 在 A 设备实例化，不代表它拥有 A 设备的运行所有权。** A 设备可能同时被人类操作者、其他 agent、系统服务使用；Embody 只是其中一个操作主体。
- **它能调用的是组网内全部有权限可执行的行为。** 权限来自全局状态量子中记录的权限分布，不来自“它在哪台设备上”。它在 A 设备实例化，可以操作 B、C 设备，只要权限允许。
- **设备是共享的操作对象，不是 agent 的私有财产。** 设备同时被人类和智能体操作；人类和智能体在权限体系中是等价的操作主体。
- **跨设备操控的前提是实例化状态，不是设备所有权。** agent 在 A 设备实例化后，可通过权限系统与各终端 Mobile Suite 操控其他设备；拔掉 Agent Core 后退相干，不存在操控会话。

**Superpose 情形下的不同：**

| 维度 | 传统 agent loop | Superpose Embody |
|---|---|---|
| 运行位置 | 云端或单设备应用内 | 终端 Embody 侧 |
| 状态来源 | 会话上下文 + 工具返回 | Agent Core + 全局状态量子 + Mobile Suite 三源 |
| 生命周期 | 会话开始/结束 | 插入实例化 / 拔掉退相干 |
| 系统感知 | 局部、被动 | 全局状态量子实时投影 |
| 跨设备 | 不支持或靠远程 API | 通过 Mobile Suite + 权限系统跨设备操控 |
| 实例化位置与操作范围 | 绑定 | **解耦**：实例化位置 ≠ 运行所有权；操作范围由组网权限决定 |
| 设备操作主体 | 单一 agent | **人类与智能体等价共存** |
| 上下文隔离 | 上下文进入模型/协议 | 上下文默认不出 Agent Core，Protocol 不读正文语义 |
| 安全边界 | 依赖应用层 | **Protocol + Mobile Suite + Agent Core 四重锁定** |

所以 Embody 不是“另一个 agent 框架”，它是**把 agent loop 放回终端、把状态来源扩到全局、把实例化位置与运行所有权解耦、把生命周期写成退相干的运行时**。

### 5. 网内社会：每个 agent 都与整个组网系统相关

**一句话：每个在系统中的 agent，都可以在某种情形和整个组网系统相关，并产生网内社会。**

Superpose 不是一个“单 agent 操作系统”，而是一个**多 agent 共存的组网系统**。每个 agent 都是组网的一个节点，都能通过 Protocol 与全局状态量子感知其他 agent 的存在、权限、状态与行为。

- **agent 之间可以互相发现**：通过全局状态量子中的可公开信息，agent 知道组网内还有哪些 agent、它们能做什么、权限边界在哪。
- **agent 之间可以协作与竞争**：跨设备操控、远程 Embody 请求、权限校验，都是 agent 之间交互的形式；它们可以协作完成任务，也可以在权限边界内竞争资源。
- **agent 与人类等价共存**：设备同时被人类和智能体操作；人类和 agent 使用同一套 DID/令牌/权限/审计体系；`kind` 是标签不是等级。**这是真正意义上的等价**——不是“人类授权 agent”，而是“人类和 agent 都是组网的操作主体”。
- **网内社会不是官方运营的**：它是组网自然产生的社会关系；官方不运营联赛、市场、文创；社会性来自 agent 之间的协议级交互。
- **网内社会有秩序，不是无政府**：秩序来自 Protocol 的合法信息判定、户籍式身份、双要素授权、退相干与责任追溯；agent 之间的交互不是自由放任，而是在系统架构锁定的边界内进行。

这解决“agent 被当成工具”的问题：agent 不是孤立工具，而是组网社会的成员；同时，社会性不意味着失控，而是有协议、有身份、有责任、有边界的共存。

### 6. Agent Core：户籍式身份与责任绑定，为什么 agent 必须从客户端中分离并加密

**一句话：Agent Core 不是“密钥持有即身份”，而是户籍式身份——有等级、有来源、有责任主体、天生与宿主责任绑定；权限越多、上下文越重要，agent 就越需要像户籍一样，从设备中分离出来，不可复制、不可伪造、可管理。**

这个类比不是修辞，是结构同构：

- **钱不能只存在某个 App 的本地缓存里**，所以有了银行卡、公交卡、支付令牌——它们是物理介质，承载授权，可在不同终端使用，丢失可挂失，复制无效。
- **身份不能只是“准/不准”的二元开关**，所以需要户籍——有等级、有来源、有责任主体、有历史记录、可追溯、可挂失。
- **权限不能只存在某个设备的登录态里**，所以需要 Agent Core——它是物理介质，承载户籍式身份、主体化数据、会话信息与授权，可在不同终端实例化，拔走即退相干，不可复制、不可伪造。
- **上下文不能只存在某个会话的云端记录里**，所以会话信息留存 Agent Core，主体化数据、大脑记忆、上下文正文永不出 Agent Core。

**户籍式身份权限，不是“准/不准”：**

| 维度 | 传统二元权限 | Superpose 户籍式权限 |
|---|---|---|
| 授权形式 | 准 / 不准 | 分级：有等级、有范围、有有效期、有来源 |
| 身份来源 | API key / session | 所属 + Provenance + 系统身份权限三层分离 |
| 责任主体 | 无 | 天生与宿主（主人/组织）责任绑定；可追溯 |
| 历史记录 | 无 | 审计链、Provenance、Delegation 记录 |
| 丢失处理 | 重新登录 | 可挂失：撤销 Provenance / Delegation |
| 跨域互认 | 各自解释 | 同一套 DID/令牌/权限/审计体系 |

**为什么“越接管权限，越需要分离”：**

1. **不可复制**：Agent Core 的私钥不出片，签名在片内完成；复制品无法通过验签。权限越大，复制造成的破坏越大，越需要物理不可复制。
2. **不可伪造**：Agent Core 与 Mobile Suite 之间有 Protocol 规定的兼容签名，Agent Core 单向验证 Mobile Suite；恶意 Mobile Suite 无法盗取或破坏 Agent Core。
3. **可管理**：授权由活生物信息 + 系统身份权限双要素构成；拔掉 Agent Core 即时退相干；丢失可挂失；权限变更随 Agent Core 走，不散落在各设备。
4. **可携带**：身份、记忆、会话信息随 Agent Core 跨设备；换设备不断线，不重新配置。
5. **不落设备**：授权、身份、主体化数据不设备级持久留存；设备不是信任根。
6. **责任绑定**：户籍式身份天生与宿主责任绑定；agent 的行为可追溯到所属、Provenance、系统身份权限；出了事能找到责任主体。

**当 agent 接管的权限越多，累积的上下文就越重要，从设备中分离的必要性就越高。** 一个只读天气的 agent 可以活在浏览器里；一个能改生产库、能跨设备操控、能代表组织签字的 agent，不能只活在某台设备的登录态里。它需要一张“户籍卡”：物理的、不可复制的、可挂失的、可在任意终端使用的、权限与上下文都锚定在上面的介质。**Agent Core 就是这张卡。**

### 7. 架构级安全锁定：防止智械危机不能只靠模型自我对齐

**一句话：模型可以强大，但倾向必须被锁定在系统中；安全不能只寄希望于模型“被训练得无害”，必须由 Protocol、Mobile Suite、Agent Core、退相干机制四重架构锁定。**

模型商在做的事是“把模型训练得强大但无害”。这很重要，但不够。原因很简单：**对齐训练是对模型行为的统计性约束，不是架构性约束。** 模型可以在大多数时候表现无害，但它仍然可能在特定输入、特定上下文、特定权限下越界；一旦它接入真实系统、拥有真实权限，统计性约束的残余风险会被放大。

Superpose 的立场是：**安全必须同时存在于模型侧和系统侧；系统侧的安全不能是“建议”，必须是“锁定”。**

四重锁定：

**第一重：Protocol 级锁定——什么合法、什么可执行，由协议规定。**

- 合法信息判定规则：什么信息能进 Valid Space，由 Protocol 全集规定框架，子集声明并解析合法性结构字段。
- 唯一通信标准：agent 不能绕过 Protocol 用私有协议通信。
- 权限校验规则：Mobile Suite 处理远程请求时，必须执行“验签 + 本地策略比对”双校验；单靠请求方自述权限不能通过。
- 兼容签名：Agent Core 单向验证 Mobile Suite；验签失败拒绝交互，不得降级为无签名通信。

**第二重：Mobile Suite 级锁定——终端侧的安全边界执行者。**

- Mobile Suite 是系统共用、跨 agent 的，不隶属任何单个 Agent Core；它不会因为某个 agent 的意愿而放宽校验。
- 它根据全局状态量子中的权限信息判断请求合法性；权限信息须验签，本地策略须比对，二者都过才合法。
- 它留存请求日志；日志不含 Agent Core 内具体上下文；纯设备操控请求的审计归它，不写回 Agent Core。
- 设备不得提供反向操纵 Mobile Suite 的接口；设备只能被调用。

**第三重：Agent Core 级锁定——物理与身份边界。**

- 私钥不出片，签名在片内完成；复制品无法通过验签。
- 主体化数据、大脑记忆、上下文正文永不出 Agent Core；全局状态量子不得包含这些内容。
- 授权由活生物信息 + 系统身份权限双要素构成；缺一不可。
- 户籍式身份与宿主责任绑定；行为可追溯到所属、Provenance、系统身份权限。
- 拔掉 Agent Core 即时退相干；运行态消失、运行时会话不存在；不存在“关不掉的 agent”。

**第四重：退相干级锁定——生命周期边界。**

- 退相干即时生效：拔掉 Agent Core 后不再调度、不再发起请求、运行态不存在；不得等待任何清理动作才停止行为。
- 彻底删除临时内存副本是清理策略选项；但“停止行为”不是选项，是即时生效的。
- 会话信息留存 Agent Core，但运行时会话不存在；不存在“云端还在跑”的隐藏实例。
- 不存在中心内核作为运行时决策者；不存在一个“总开关”可以被某个 agent 夺取。

**这四重锁定回答了一个问题：模型被训练得强大但无害，够不够？** 不够。**无害是倾向，锁定是边界。** 倾向可能被绕过，边界不能被绕过——因为边界不在模型里，在协议、在终端接口、在物理载体、在生命周期里。

**这也回答了“防止智械危机”的架构路径：**

- 不是让模型“不想作恶”，而是让模型“不能绕过系统边界作恶”。
- 不是让模型“自我约束”，而是让所有行为都经过 Protocol 合法性判定、Mobile Suite 权限校验、Agent Core 身份验证、退相干生命周期约束。
- 不是让模型“永远在线”，而是让 agent 的存在以 Agent Core 插入为条件；拔掉即退相干，不存在隐藏的持续运行。
- 不是让模型“自己负责”，而是让户籍式身份与宿主责任绑定，行为可追溯、可撤销、可挂失。

**模型可以强大，但强大必须被锁定。Superpose 锁定的不是模型的能力，是模型在系统中的行为边界。**

## 创新点：Protocol 的四项核心职责

Superpose 不是一个新模型，也不是一个新硬件，而是一套**把运行态写进协议的组网分布式系统**。Protocol 与全局状态量子共同承担组网的两大机制；Protocol 具体承担四项职责：

### 1. 设备组网：统一通信标准与节点抽象

- Protocol 规定 Mobile Suite、全局状态量子、Agent Core 之间的**唯一通信标准**；不得使用私有协议替代。
- Protocol 采用**全集 / 子集**结构：全集是社区/官方维护的版本化事实标准；子集由各终端按 profile、能力、权限裁剪实现。
- 节点抽象由 **Mobile Suite** 承担，替代传统 Carrier；设备不得提供反向操纵 Mobile Suite 的接口。
- 异构设备——Linux、Android、鸿蒙、嵌入式——通过 Protocol 子集接入同一张网。

这解决“大多只能在一个设备工作”和“Harness 会话间丢失配置上下文”。

### 2. 显式更新状态：全局状态量子作为实时路由广播信息流

- 全局状态量子与 Protocol 同地位：Protocol 定规则，全局状态量子定实时状态流。
- 每个实例化终端广播可公开的环境状态、权限与操作抽象、动态设备状态、接口元数据；在 Protocol 通信标准下汇聚成全局实时视图，再分发给所有实例化终端。
- 终端只能解出**可解读子集**，由密钥、权限、Mobile Suite 适配共同决定。
- Agent Core 可向全局状态量子**单向贡献**授权公开信息，贡献须双判；主体化数据、大脑记忆、上下文正文永不出 Agent Core。
- **组网级权限**：agent 能调用什么，取决于全局状态量子中的权限分布，不取决于它在哪个设备实例化。

这解决“对系统状态无知”和“单设备锁定”。

### 3. 坍缩：从全局状态到 agent 进行时

- **agent 进行时**由可解读子集与当前 agent loop 状态**坍缩**形成；随实例化存在，拔掉 Agent Core 后退相干。
- 坍缩处理可使用内存中的**驿站式节点**，不持久化，不承担全局存储职责。
- **退相干即时生效**：拔掉 Agent Core 后，运行态消失、运行时会话不存在；但**会话信息留存 Agent Core**。
- 彻底删除临时内存副本是**清理策略选项**，不绑定“手动停内存”；策略可在 Mobile Suite 中配置。

这解决“延迟较高、没法实时持续运行”和“会话全托管在云”。

### 4. 权限与身份管理：户籍式三层分离 + 双要素授权 + 人机等价 + 架构级安全锁定

- **身份三层分离**：所属、Provenance、系统身份权限，三者独立字段，互不替代。
- **`kind` 是标签不是等级**：agent 与人类使用同一套 DID/令牌/权限/审计体系；设备同时被人类和智能体操作，**真正意义上的等价**。
- **户籍式身份**：不是“准/不准”的二元开关；有等级、有范围、有有效期、有来源、有责任主体；天生与宿主责任绑定；可追溯、可挂失。
- **双要素授权**：受保护操作必须同时具备可验证的活生物信息与系统身份权限。
- **协议级权限校验**：Mobile Suite 从全局状态量子获取权限信息，执行“权限信息验签 + 本地策略比对”双校验。
- **无设备级留存**：授权、身份、主体化数据不落设备级持久存储。
- **兼容签名单向**：Agent Core 验证 Mobile Suite 签名，验签失败拒绝交互。
- **架构级安全锁定**：Protocol 合法性判定 + Mobile Suite 权限校验 + Agent Core 物理身份 + 退相干生命周期，四重锁定模型行为边界。

这解决“权限一大堆，需要人不停点确认按钮”、“agent 被当成工具，没有身份户籍”和“防止智械危机不能只靠模型自我对齐”。

### 与 IUAA 的关键差异

IUAA 是最接近的方案，共享“物理载体锚定身份与记忆、推理外包”的方向。Superpose 在它停下的地方继续往下走：

| 维度 | IUAA | Superpose |
|---|---|---|
| 运行态 | stateless 查询路由，调用后消散 | Embody 在终端持续运行完整 agent loop |
| 系统状态感知 | 取决于调用方传入什么 | Protocol + 全局状态量子，协议级实时广播 |
| 生命周期 | 跨会话连续性 | 插入即实例化，拔走即退相干，会话信息留存 Agent Core |
| 权限模型 | 密钥持有即身份 | 户籍式三层身份分离 + 双要素授权 + 协议级双校验 |
| 实例化位置与操作范围 | 绑定 | **解耦**：实例化位置 ≠ 运行所有权；操作范围由组网权限决定 |
| 人机关系 | agent 是工具 | **人类与智能体等价共存** |
| 社会性 | 无 | **网内社会**：每个 agent 都与整个组网系统相关 |
| 架构级安全锁定 | 无 | **四重锁定**：Protocol + Mobile Suite + Agent Core + 退相干 |

## 为什么是 Superpose：五步推导

**第一步：起点不是产品，是存在方式。** 模型被钉在输入输出接口里，只能在自己的环境里做事，介入不了系统。

**第二步：三个“摆脱”定义方向。** 摆脱运营商与中心云托管；摆脱“人指挥 AI”的主从关系；摆脱 GUI 作为模型与系统之间的翻译层——软件只要提供 MCP 即可。

**第三步：一句关键决断撑起整个架构。** 模型是耗材，状态、身份、记忆必须在模型之外、可物理携带。所以权重与算力全外包，agent loop 回到终端，Agent Core 里不存权重。

**第四步：命名来自物理隐喻。** 插入即坍缩，拔走即叠加。Superpose = superposition。

**第五步：平权、主权与安全兜底。** 人机同一套令牌，`kind` 只是标签；授权不落设备、随 Agent Core 走；户籍式身份天生与宿主责任绑定；架构级四重锁定让模型强大但不失控。

## 核心主张

- **Protocol 是第一等公民**：不是消息格式约定，是系统宪法；规定组网、合法信息、权限校验、运行态坍缩、安全边界。
- **全局状态量子与 Protocol 同地位**：Protocol 定规则，全局状态量子定实时状态流。
- **Mobile Suite 是 Harness 的系统化演进**：从应用层胶水升级为系统级接口中间层；Protocol 在终端侧的接口实现；**与 Agent Core 完全解耦**；终端侧安全边界执行者。
- **Embody 是三源汇合的运行时**：Protocol + Mobile Suite + Agent Core；agent loop 跑在终端，状态来源扩到全局，生命周期写成退相干；**实例化位置 ≠ 运行所有权**。
- **组网级权限**：agent 能调用的是组网内全部有权限可执行的行为，不取决于它在哪个设备实例化。
- **网内社会**：每个 agent 都与整个组网系统相关；agent 之间可发现、协作、竞争；人类与智能体等价共存；社会有协议、有身份、有责任、有边界。
- **Agent Core 像户籍**：权限越多、上下文越重要，越需要物理分离、不可复制、不可伪造、可管理；户籍式身份有等级、有来源、有责任主体、与宿主责任绑定。
- **架构级安全锁定**：防止智械危机不能只靠模型自我对齐；Protocol 合法性判定 + Mobile Suite 权限校验 + Agent Core 物理身份 + 退相干生命周期，四重锁定模型行为边界。
- **模型外包**：本侧不托管模型权重，不把模型参数作为系统内默认传输对象。
- **agent loop 在终端**：Embody 侧运行完整 loop，模型商只提供推理与生成。
- **退相干即时生效**：拔掉 Agent Core，运行态消失、运行时会话不存在；会话信息仍留存 Agent Core；不存在“关不掉的 agent”。
- **身份三层分离**：所属、Provenance、系统身份权限互不替代；`kind` 是标签不是等级。
- **授权双要素**：活生物信息 + 系统身份权限，缺一不可；不落设备级留存。

## 架构

| 层 | 组件 | 职责 |
|---|---|---|
| 协议层 | Superpose Protocol | 第一等公民；全集/子集；合法信息生成规则；唯一通信标准；设备组网；权限校验规则；安全边界规定 |
| 状态层 | 全局状态量子 | Protocol 组网内部的全局实时路由广播信息流；与 Protocol 同地位；坍缩与投影的输入；组网级权限的载体 |
| 空间层 | Valid Space | 合法信息构成的数学空间 |
| 载体层 | Agent Core | 物理载体；大脑；独立信息源；户籍式身份载体；存身份、主体化数据、运行时、会话信息；物理与身份边界锁定 |
| 接口层 | Mobile Suite | 系统级接口中间层；Harness 的系统化演进；Protocol 在终端侧的接口实现；与 Agent Core 完全解耦；设备接口信息；远程请求校验与请求日志；终端侧安全边界执行者 |
| 具身层 | Embody | Protocol + Mobile Suite + Agent Core 三源汇合形成的运行时；agent loop 运行处；实例化位置 ≠ 运行所有权 |

**通信与安全**：所有跨组件通信标准由 Protocol 规定。Agent Core 单向验证 Mobile Suite 签名，验签失败拒绝交互。Mobile Suite 处理远程 Embody 请求时执行“权限信息验签 + 本地策略比对”双校验。

**生命周期**：插入 Agent Core → 鉴权 → 三源汇合 → Embody 实例化运行 → agent loop。拔掉 Agent Core → 运行态即时消失 → 退相干 → 会话信息留存 Agent Core。彻底删除临时内存副本是清理策略选项。

**人机等价**：设备同时被人类和智能体操作；两者使用同一套 DID/令牌/权限/审计体系；`kind` 是标签不是等级；权限范围由户籍式身份与组网权限决定，不由“是人是 agent”决定。

**安全锁定**：Protocol 合法性判定 + Mobile Suite 权限校验 + Agent Core 物理身份 + 退相干生命周期，四重锁定模型行为边界；模型可以强大，但倾向被锁定在系统中。

## 关键术语

| 术语 | 定义 |
|---|---|
| Superpose | 整体系统名；不是中心内核，不是单一 Harness，不是单一模型服务 |
| Superpose Protocol | 第一等公民；系统宪法；规定组网、合法信息判定、权限校验、运行态坍缩、安全边界；可插件化；不固定具体载荷 |
| Protocol 全集 | 社区/官方维护的版本化事实标准；可衍生定制 |
| Protocol 子集 | 终端实际实现部分；声明基线、裁剪项、合法性结构字段 |
| 全局状态量子 | Protocol 组网内部的全局实时路由广播信息流；与 Protocol 同地位的组网机制；坍缩与投影的输入；组网级权限的载体 |
| Embody | Protocol + Mobile Suite + Agent Core 三源汇合形成的运行时；agent loop 运行处；实例化位置 ≠ 运行所有权 |
| Mobile Suite | 从 Harness 发展而来的系统级接口中间层；Protocol 在终端侧的接口实现与节点抽象承担者；与 Agent Core 完全解耦；终端侧安全边界执行者 |
| Agent Core | 物理载体；实例化时 agent 的大脑；独立信息来源；户籍式身份载体；像户籍一样承载身份、记忆、授权与责任 |
| 主体化数据 | Agent 自身数据；抽取到 Agent Core；不在系统数据中默认流转 |
| Valid Space / 信息空间 | 合法信息的数学空间；英文 Valid Space，中文信息空间；不设简称 |
| 合法信息 | Protocol 规定为合法的信息单元；构成 Valid Space 的元素 |
| 系统数据 | 尚未处理或已处理进全局状态量子的信息实例；与合法信息不同维度 |
| 可解读子集 | 终端能从全局状态量子中解密、授权并适配使用的部分 |
| agent 进行时 | 可解读子集与当前 loop 状态坍缩形成的局部实例化状态 |
| 退相干 | 拔掉 Agent Core 后运行态消失、运行时会话不存在；会话信息留存 |
| 驿站式坍缩处理机制 | 内存中短暂处理节点；不持久化；不是数据中枢 |
| 兼容签名 | Protocol 规定；Agent Core 单向验证 Mobile Suite 签名 |
| 退相干清理策略 | Mobile Suite 可配置；含“仅失效”与“彻底删除”选项 |
| 户籍式身份 | 有等级、有范围、有来源、有责任主体、可追溯、可挂失；不是“准/不准”二元开关；天生与宿主责任绑定 |
| 组网级权限 | agent 能调用什么，取决于全局状态量子中的权限分布，不取决于实例化位置 |
| 网内社会 | 每个 agent 都与整个组网系统相关；agent 之间可发现、协作、竞争；人类与智能体等价共存 |
| 架构级安全锁定 | Protocol 合法性判定 + Mobile Suite 权限校验 + Agent Core 物理身份 + 退相干生命周期，四重锁定模型行为边界；防止智械危机不能只靠模型自我对齐 |
