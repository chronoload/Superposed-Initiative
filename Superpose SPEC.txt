--------------------------------------------------------------------------------
0. 系统定位与总则
--------------------------------------------------------------------------------
0.1 Superpose 是可定制的组网分布式系统体系，由 Protocol、Embody、Mobile Suite、
    Agent Core、全局状态量子、Valid Space 等组成。
0.2 模型参数与计算默认全部外包给模型提供商；本侧不托管模型权重，不把模型参数作为
    系统内默认传输对象。
0.3 agent loop 全在终端 Embody 侧；模型商只提供推理/生成。
0.4 Agent Core 是物理载体，也是实例化时 agent 的大脑与独立信息来源；不是全局状态
    量子的子集，不得简写为 Core。
0.5 Mobile Suite 是系统共用的公共接口中间层，与 agent 化无关；不隶属单个 Agent Core。
0.6 Mobile Suite、全局状态量子、Agent Core 之间的唯一通信标准由 Protocol 规定；
    不得使用私有通信协议替代。
0.7 Valid Space 是数学上的合法信息空间，由所有 Protocol 规定的合法信息构成；
    全局状态量子是 Valid Space 中的一个点；禁止表述为“状态写入空间”。
0.8 合法信息判定：Protocol 全集规定“合法性必须可判定”；各子集声明并解析合法性
    结构字段；合法后允许传输加密内容；子集不读取加密正文语义。
0.9 审计归属：涉及 Agent Core 内部状态的动作写回 Agent Core；纯设备操控请求归
    Mobile Suite 请求日志。
0.10 退相干：拔掉 Agent Core 后，实例化运行态即时消失、与全局状态量子退相干、
     运行时会话不存在；会话信息留存 Agent Core；彻底删除临时内存副本是清理策略
     选项，不绑定“手动停内存”这一具体动作。

--------------------------------------------------------------------------------
1. 核心术语
--------------------------------------------------------------------------------
1.1 Superpose：整体系统名。
1.2 Superpose Protocol：协议/共识层；可插件化/组件化；不固定具体载荷。
1.3 Protocol 全集：社区/官方维护的版本化事实标准；包含可选组件、消息类型、规则与
    扩展点；可衍生定制。
1.4 Protocol 子集：终端 Mobile Suite 或 Agent Core 实际实现的部分；必须声明基线版本、
    裁剪项与合法性结构字段。
1.5 Embody：终端具身 agent 系统；agent loop 全在终端；由三源汇合形成。
1.6 Mobile Suite：系统共用公共接口中间层；由终端 OS 按 Protocol 预装/热更新；
    提供设备接口信息；校验远程 Embody 请求并留请求日志。
1.7 Agent Core：物理载体；存主体化数据、身份、Embody 运行时、Protocol 终端实现、
    兼容发行包、会话信息；不存模型参数；不默认存系统数据。
1.8 主体化数据：Agent 自身数据，抽取到 Agent Core，不在系统数据中默认流转。
1.9 全局状态量子：Valid Space 中的一个点；一个具体全局状态，也是系统内信息流；
    包含环境状态、权限与操作抽象、动态设备状态、接口元数据等合法信息。
1.10 Valid Space / 信息空间：合法信息的数学空间；英文正式名 Valid Space，中文正式名
     信息空间；不设简称。
1.11 合法信息：由 Protocol 规定为合法的信息单元；构成 Valid Space 的元素。
1.12 系统数据：尚未处理或已经被处理进全局状态量子的信息实例；来源可为 Agent Core、
     Mobile Suite、成员权限协议；与合法信息是不同维度。
1.13 可解读子集：某终端实例能从全局状态量子中解密、授权并适配使用的部分。
1.14 agent 进行时：可解读子集与当前 agent loop 状态坍缩形成的局部实例化状态。
1.15 退相干：拔掉 Agent Core 后，agent 与全局状态量子失去相干性；运行态消失；
     会话信息仍留存于 Agent Core。

--------------------------------------------------------------------------------
2. 架构总则
--------------------------------------------------------------------------------
2.1 层级
    Superpose
      ├─ Superpose Protocol：全集/子集/合法信息生成规则
      ├─ Valid Space：合法信息的数学空间
      │    └─ 全局状态量子：空间中的一个点/信息流
      ├─ Agent Core：物理载体/大脑/独立信息源
      ├─ Mobile Suite：系统共用接口中间层
      └─ Embody：Agent Core + 全局状态量子 + Mobile Suite 设备接口信息 三源汇合

2.2 通信
    所有跨组件通信标准由 Protocol 规定。
    Agent Core 验证 Mobile Suite 签名；单向验证；验签失败拒绝交互。
    Mobile Suite 处理远程 Embody 请求时执行“权限信息验签 + 本地策略比对”双校验。

2.3 状态与生命周期
    插入 Agent Core → 鉴权 → 三源汇合 → 实例化运行 → agent loop
    拔掉 Agent Core → 运行态即时消失 → 退相干 → 会话信息留存 Agent Core
    彻底删除临时内存副本由清理策略选择，不绑定手动操作。

2.4 非目标
    不设中心内核；不以 Carrier 作为节点抽象；不以数据中枢作为全局存储组件；
    不做设备绑定/设备级信任根；不在本侧托管模型权重。

================================================================================
3.1 Protocol 域
================================================================================

[SPEC-PR-001] 状态：草案｜模态：必须
条件：Protocol 规范存在。
行为：维护版本化 Protocol 全集，包含可选组件、消息类型、规则与扩展点；由社区/官方
      作为事实标准维护；个人/组织可衍生定制。
验收：存在全集版本号与清单；衍生版本可声明基线版本。
缺口：全集清单。

[SPEC-PR-002] 状态：草案｜模态：必须
条件：终端 Mobile Suite 或 Agent Core 实现 Protocol 子集。
行为：子集必须声明基线版本、裁剪项、合法性结构字段；不同终端子集可不同。
验收：子集声明可读；合法性结构字段存在；可追溯到全集版本。
缺口：子集裁剪规则。

[SPEC-PR-003] 状态：草案｜模态：必须
条件：任何信息要进入 Valid Space。
行为：Protocol 全集规定合法信息判定规则框架；子集按声明的合法性结构字段执行判定；
      只有合法信息构成 Valid Space 元素。
验收：给定信息可按子集字段判定合法/非法；非法信息不进入 Valid Space。
缺口：判定规则细节。

[SPEC-PR-004] 状态：草案｜模态：必须
条件：描述 Valid Space 与合法信息关系。
行为：Valid Space 由所有合法信息构成；不得表述为“状态写入空间”；不得把 Valid Space
      等同于某个具体状态。
验收：范畴检查通过；无“写入空间”表述。
缺口：无。

[SPEC-PR-005] 状态：草案｜模态：必须
条件：Mobile Suite、全局状态量子、Agent Core 之间通信。
行为：唯一通信标准由 Protocol 规定；不得使用私有通信协议替代。
验收：接口清单只引用 Protocol 消息类型；无私有协议条目。
缺口：消息类型清单。

[SPEC-PR-006] 状态：草案｜模态：必须
条件：Agent Core 与 Mobile Suite 建立交互。
行为：Agent Core 必须验证 Mobile Suite 签名；Agent Core 不向 Mobile Suite 证明自己；
      验签失败不得交互。
验收：恶意 Mobile Suite 无法通过 Agent Core 验签；无签名交互被拒绝。
缺口：签名算法与密钥分发。

[SPEC-PR-007] 状态：草案｜模态：不得
条件：Agent Core 验证 Mobile Suite 签名失败。
行为：不得降级为无签名通信；不得继续交换主体化数据或会话信息；必须拒绝交互并记录事件。
验收：失败时无数据交换；事件可追溯。
缺口：事件格式。

[SPEC-PR-008] 状态：草案｜模态：必须
条件：Mobile Suite 处理远程 Embody 请求。
行为：Protocol 规定 Mobile Suite 如何从全局状态量子获取权限信息，并执行“验签 + 本地
      策略比对”双校验；二者都过才合法。
验收：合法/非法请求判定可追溯到 Protocol 规则；单靠请求方自述权限不能通过。
缺口：校验规则细节。

[SPEC-PR-009] 状态：草案｜模态：必须
条件：终端 OS 预装或热更新 Mobile Suite。
行为：Protocol 规定预装基线、热更新兼容签名与版本协商；更新后的 Mobile Suite 必须能
      通过 Agent Core 验签。
验收：热更新后验签通过才交互；版本不兼容时拒绝或降级。
缺口：预装基线/降级策略。

[SPEC-PR-010] 状态：草案｜模态：可以
条件：用户或组织选择 Protocol 包涵内容。
行为：Protocol 可插件化/组件化，用户可自选组件集；不得破坏合法信息判定与唯一通信标准。
验收：插件清单存在；启用插件后合法信息判定仍可执行。
缺口：插件清单。

[SPEC-PR-011] 状态：草案｜模态：可以
条件：个人/组织需要定制 Protocol。
行为：可衍生定制版本；必须声明基线版本与差异；不得自称事实标准全集。
验收：衍生版本可追溯基线；差异清单存在。
缺口：治理流程。

[SPEC-PR-012] 状态：草案｜模态：不得
条件：Protocol 运行时。
行为：不得存在中心内核作为运行时决策者；Protocol 全集是规范，不是运行时中心；
      不得单写 Core 指代 Agent Core。
验收：运行时无中心内核依赖；术语表中无 Core 简称。
缺口：无。

[SPEC-PR-013] 状态：草案｜模态：必须
条件：Protocol 定义合法信息。
行为：至少覆盖环境状态、权限与操作抽象、动态设备状态、接口元数据等类别；接口元数据
      与权限操作抽象并列，不互相替代。
验收：类别清单存在；各类别可判定合法/非法。
缺口：类别字段。

[SPEC-PR-014] 状态：草案｜模态：必须
条件：任何载荷要经 Protocol 传输。
行为：全集规定“合法性必须可判定”；子集声明并解析合法性结构字段；合法的允许传输
      加密内容；非法的不得传输；子集不读取加密正文语义。
验收：非法载荷被拒绝；合法加密载荷可传输；子集声明合法性结构字段。
缺口：合法性结构字段清单与加密格式。

[SPEC-PR-015] 状态：草案｜模态：必须
条件：Agent Core 携带 Protocol 终端实现。
行为：Agent Core 必须声明 Protocol 子集版本与兼容签名信息；Mobile Suite 交互前按
      Protocol 规则核对兼容性。
验收：子集版本可读；不兼容时拒绝或降级。
缺口：兼容性矩阵。

3.2 Valid Space / 全局状态量子域
================================================================================

[SPEC-VS-001] 状态：共识｜模态：必须
条件：任何合法信息存在。
行为：Valid Space 必须由所有合法信息构成；不得表述为“状态写入空间”；不得等同于
      某个具体状态。
验收：空间由合法信息构成；无“写入空间”表述；不指向单一状态。
缺口：合法信息类别字段。

[SPEC-VS-002] 状态：共识｜模态：必须
条件：描述全局状态量子与 Valid Space 关系。
行为：全局状态量子必须是 Valid Space 中的一个点；不得表述为同层、包含或“空间写入状态”。
验收：全局状态量子是点，Valid Space 是空间；无“量子=空间”表述。
缺口：无。

[SPEC-VS-003] 状态：共识｜模态：必须
条件：构造全局状态量子。
行为：至少包含环境状态、权限与操作抽象、动态设备状态、接口元数据；接口元数据与
      权限操作抽象并列。
验收：类别清单存在；各类别可判定合法/非法；无类别缺失。
缺口：类别字段。

[SPEC-VS-004] 状态：共识｜模态：必须
条件：Mobile Suite、Agent Core、全局状态量子之间通信。
行为：全局状态量子作为系统内信息流存在；通信标准由 Protocol 规定；不得使用私有协议。
验收：接口清单只引用 Protocol 消息类型；无私有协议条目。
缺口：消息类型清单。

[SPEC-VS-005] 状态：共识｜模态：必须
条件：终端实例读取全局状态量子。
行为：终端只能解出可解读子集；由密钥、权限、Mobile Suite 适配共同决定；不同终端可不同。
验收：无权限/无密钥终端解不出受保护内容；不同终端可解读子集可不同。
缺口：判定规则。

[SPEC-VS-006] 状态：共识｜模态：必须
条件：agent 在终端实例化。
行为：agent 进行时由可解读子集与当前 agent loop 状态坍缩形成；随实例化存在；
      拔掉 Agent Core 后退相干。
验收：实例化期间存在 agent 进行时；退相干后不存在。
缺口：字段。

[SPEC-VS-007] 状态：共识｜模态：可以
条件：全局状态量子在终端坍缩。
行为：可使用内存中短暂处理节点（驿站）作为坍缩处理机制；不得持久化；不得承担全局
      存储职责。
验收：驿站节点不落持久存储；进程结束后无残留。
缺口：生命周期。

[SPEC-VS-008] 状态：共识｜模态：必须
条件：全局状态量子与 Agent Core 同时存在。
行为：二者为并行双源；Agent Core 可向全局状态量子单向贡献授权公开信息；贡献必须同时
      通过 Agent Core 自检与权限系统授权；全局状态量子不得因此包含主体化数据、大脑记忆、
      上下文正文。
验收：双源可区分；贡献有双判记录；禁止项不可在量子中检索。
缺口：贡献可撤销性。

[SPEC-VS-009] 状态：共识｜模态：不得
条件：任何时刻。
行为：全局状态量子不得包含 Agent Core 主体化数据、大脑记忆、上下文正文；不得成为这些
      内容的存储或中转。
验收：量子内容清单中无上述三类；中转路径检查无命中。
缺口：检测手段。

3.3 Embody 域
================================================================================

[SPEC-EM-001] 状态：共识｜模态：必须
条件：agent 在终端实例化。
行为：Embody 必须由三源汇合——Agent Core、全局状态量子、Mobile Suite 提供的设备接口
      信息；不得只等于其中任一源。
验收：三源均可识别；缺任一源时实例化失败或降级。
缺口：三源汇合优先级。

[SPEC-EM-002] 状态：共识｜模态：必须
条件：agent 运行。
行为：agent loop 必须全在终端 Embody 侧；模型商只提供推理/生成；不得把 loop 放在
      Protocol 或 Mobile Suite 内。
验收：Embody 进程内含 loop 调度；Protocol/Mobile Suite 内无 loop 调度。
缺口：loop 状态机细节。

[SPEC-EM-003] 状态：共识｜模态：不得
条件：术语使用。
行为：终端具身系统必须称 Embody；不得称 Harness；Harness 旧称只留在修正链。
验收：术语表与接口中无 Harness 指代 Embody。
缺口：无。

[SPEC-EM-004] 状态：共识｜模态：必须
条件：插入/拔掉 Agent Core。
行为：插入后 Embody 激活并实例化；拔掉后实例化运行态消失、与全局状态量子退相干、
      运行时会话不存在；不得表述为“会话终止但可恢复”。
验收：拔掉后无运行态调度；无运行时会话；退相干状态可观测。
缺口：残留内存副本清理。

[SPEC-EM-005] 状态：共识｜模态：必须
条件：退相干后。
行为：会话信息必须留存于 Agent Core；运行时会话不存在不等于会话信息消失；重新插入后
      可读取。
验收：退相干后 Agent Core 可读取上次会话信息；退相干期间不产生新会话信息。
缺口：会话信息格式。

[SPEC-EM-006] 状态：共识｜模态：必须
条件：agent 实例化期间。
行为：运行时会话必须作用于整个 Superpose 系统与全局状态量子；不得定义为单设备登录
      会话；以实例化为存在前提。
验收：会话状态可跨设备观测；拔掉 Agent Core 后会话不存在。
缺口：会话状态字段。

[SPEC-EM-007] 状态：共识｜模态：可以
条件：agent 在 A 终端实例化。
行为：可通过权限系统与各终端 Mobile Suite 操控其他设备；操控前提是 agent 处于实例化
      状态；拔掉 Agent Core 后退相干，不存在操控会话。
验收：实例化期间可发起跨设备请求；退相干后请求不再被该实例发起。
缺口：跨设备权限模型。

[SPEC-EM-008] 状态：共识｜模态：必须
条件：Embody 与 Protocol 交互。
行为：Embody 的具体上下文不得默认进入 Protocol；隔离为设计原则；通信标准仍由 Protocol
      规定，但 Protocol 不读取上下文正文语义。
验收：Protocol 消息中无上下文正文；Embody 侧有隔离声明。
缺口：可选明文组件。

[SPEC-EM-009] 状态：共识｜模态：可以
条件：Embody 部署。
行为：可兼容 Linux、Android、鸿蒙、嵌入式等多系统多设备；兼容性由 Mobile Suite 适配
      与 Protocol 子集共同决定。
验收：至少两类终端可运行 Embody；适配差异可追溯。
缺口：多 OS 适配清单。

================================================================================
3.4 Agent Core 域
================================================================================

[SPEC-AC-001] 状态：草案｜模态：必须
条件：Agent Core 插入终端并完成鉴权。
行为：Agent Core 必须作为实例化时 agent 的大脑与独立信息来源存在；不得被定义为全局
      状态量子的子集。
验收：插入后 Embody 能读取 Agent Core 提供的身份与会话信息；移除后该信息来源消失。
缺口：无。

[SPEC-AC-002] 状态：草案｜模态：必须
条件：Agent Core 处于可读状态。
行为：必须存放主体化数据、身份、Embody 运行时、Protocol 终端实现、兼容发行包、会话信息。
验收：六类内容均可从 Agent Core 侧被对应组件读取；缺任一类时实例化失败或降级。
缺口：六类内容字段。

[SPEC-AC-003] 状态：草案｜模态：不得
条件：任何实例化或运行过程中。
行为：Agent Core 不得存放模型参数；不得默认存放系统数据。
验收：内容清单中无模型权重文件；系统数据默认不落 Agent Core。
缺口：系统数据例外清单。

[SPEC-AC-004] 状态：草案｜模态：不得
条件：Agent Core 向全局状态量子贡献信息时。
行为：主体化数据、大脑记忆、上下文正文不得出 Agent Core；贡献必须同时通过 Agent Core
      自检与权限系统授权，缺一不可。
验收：全局状态量子中检索不到上述三类；贡献清单同时有自检与授权记录。
缺口：禁止项检测手段。

[SPEC-AC-005] 状态：草案｜模态：必须
条件：终端插入 Agent Core 后执行生物验证。
行为：生物比对必须以 Agent Core 内比对为主；终端只起辅助计算作用，可提供识别但不作
      最终结论。
验收：终端伪造 match 不能单独完成鉴权；Agent Core 内比对失败时拒绝实例化。
缺口：生物源与活体检测。

[SPEC-AC-006] 状态：草案｜模态：必须
条件：Agent Core 被拔掉。
行为：agent 实例化运行态必须消失，与全局状态量子退相干，运行时会话不存在。
验收：拔掉后终端侧无该 agent 运行态；远程请求不再被该实例发起。
缺口：残留内存副本清理。

[SPEC-AC-007] 状态：草案｜模态：必须
条件：拔掉 Agent Core 后。
行为：会话信息必须留存于 Agent Core；运行时会话不存在不等于会话信息消失。
验收：重新插入后可读取上次会话信息；退相干期间不产生新会话信息。
缺口：会话信息格式。

[SPEC-AC-008] 状态：草案｜模态：可以
条件：Agent Core 选择向全局状态量子贡献信息。
行为：可单向贡献授权公开的会话/身份元数据与非主体化可公开部分；不得贡献主体化数据、
      大脑记忆、上下文正文；贡献须双判。
验收：贡献内容可在量子中检索；双判记录齐全；禁止项不可检索。
缺口：贡献可撤销性。

[SPEC-AC-009] 状态：草案｜模态：必须
条件：发生涉及 Agent Core 内部状态的动作。
行为：该动作审计必须写回 Agent Core；纯设备操控请求不写回 Agent Core，归 Mobile Suite
      请求日志；分类以发起方为准。
验收：Agent Core 审计记录含内部状态动作；Mobile Suite 日志含纯操控请求；二者不重复。
缺口：Core 内部状态动作分类边界。

[SPEC-AC-010] 状态：草案｜模态：不得
条件：任何运行时刻。
行为：Agent Core 不得与 Mobile Suite 合并为同一组件；Mobile Suite 不隶属单个 Agent Core。
验收：移除某 Agent Core 后 Mobile Suite 仍在终端可用；Mobile Suite 日志不写入 Agent Core
      主体化区。
缺口：无。

================================================================================
3.5 Mobile Suite 域
================================================================================

[SPEC-MS-001] 状态：草案｜模态：必须
条件：终端运行 Mobile Suite。
行为：Mobile Suite 必须作为系统共用的公共接口中间层存在，与 agent 化无关。
验收：无 Agent Core 插入时 Mobile Suite 仍可被系统调用；多个 Agent Core 先后插入均使用
      同一 Mobile Suite。
缺口：无。

[SPEC-MS-002] 状态：草案｜模态：必须
条件：终端 OS 部署或热更新 Mobile Suite。
行为：Mobile Suite 由终端 OS 按 Protocol 规范预装/热更新；不得依赖运行时中心派发；
      更新后必须能通过 Agent Core 验签。
验收：无中心连接时 Mobile Suite 仍存在并可启动；热更新后验签通过才交互。
缺口：预装接口。

[SPEC-MS-003] 状态：草案｜模态：不得
条件：组网节点抽象。
行为：不得再以 Carrier 作为节点抽象；节点抽象职责由 Mobile Suite 承担。
验收：术语表与接口中无 Carrier 条目；节点能力由 Mobile Suite 暴露。
缺口：无。

[SPEC-MS-004] 状态：草案｜模态：不得
条件：任何运行时刻。
行为：Mobile Suite 不得承载 agent loop；agent loop 全在 Embody 侧。
验收：Mobile Suite 进程内无 agent loop 调度；关闭 Embody 后 Mobile Suite 仅保留接口能力。
缺口：无。

[SPEC-MS-005] 状态：草案｜模态：不得
条件：设备与 Mobile Suite 交互。
行为：设备不得提供反向操纵 Mobile Suite 的接口；设备只能被调用。
验收：设备侧接口清单中无改写 Mobile Suite 权限/逻辑的入口。
缺口：审计手段。

[SPEC-MS-006] 状态：草案｜模态：必须
条件：Embody 实例化。
行为：Mobile Suite 必须向 Embody 提供设备自身接口信息，包括静态接口元数据与动态设备
      状态。
验收：Embody 可读取设备接口信息；断开 Mobile Suite 后 Embody 无法访问设备接口。
缺口：设备接口分类。

[SPEC-MS-007] 状态：草案｜模态：必须
条件：收到远程 Embody 请求。
行为：目标 Mobile Suite 必须根据全局状态量子中的权限信息自行判断请求是否合法；执行
      “验签 + 本地策略比对”双校验；合法执行，非法拒绝。
验收：合法请求被执行；非法请求被拒绝；判断不依赖请求方自述权限。
缺口：合法性判断规则。

[SPEC-MS-008] 状态：草案｜模态：必须
条件：Mobile Suite 处理远程 Embody 请求后。
行为：必须留存请求日志；日志不包含 Agent Core 内具体上下文。
验收：每条远程请求有对应日志；日志中无主体化数据与上下文正文。
缺口：请求日志格式。

[SPEC-MS-009] 状态：草案｜模态：必须
条件：纯设备操控请求。
行为：该请求审计必须归 Mobile Suite 请求日志；不得写回 Agent Core 作为唯一审计；
      分类以发起方为准。
验收：纯操控请求在 Agent Core 审计中不重复出现；Mobile Suite 日志可追溯。
缺口：纯操控请求边界。

[SPEC-MS-010] 状态：草案｜模态：不得
条件：任何运行时刻。
行为：Mobile Suite 不得持久化主体化数据；不得成为设备级信任根。
验收：Mobile Suite 存储中无主体化数据；拔掉 Agent Core 后无 agent 主体化残留。
缺口：临时内存态清理。

================================================================================
3.6 身份 / 所属 / 权限域
================================================================================

[SPEC-ID-001] 状态：共识｜模态：必须
条件：Agent 入网或跨域交互。
行为：Agent 身份令牌必须与人类使用同一套 DID/令牌/权限/审计体系；不得为 Agent 另设
      低等级通道。
验收：Agent 与人类令牌结构一致；权限表、审计链同一套；无 Agent 专用降级字段。
缺口：身份令牌格式。

[SPEC-ID-002] 状态：共识｜模态：必须
条件：身份令牌声明 kind 字段。
行为：kind 只能作为标签（agent/human 等），不得作为权限等级依据；权限由系统身份权限
      与所属/委托决定。
验收：kind=agent 不自动降权；同权限配置下 agent 与人类可获同等范围。
缺口：kind 标签枚举。

[SPEC-ID-003] 状态：共识｜模态：必须
条件：声明 Agent 所属。
行为：所属必须指向主人/组织/部门/项目；必须与 Agent 自身身份分离，不得混为同一字段。
验收：身份与所属可分别读取；修改所属不改变 Agent 身份标识。
缺口：所属链字段。

[SPEC-ID-004] 状态：共识｜模态：必须
条件：Agent 被签发或派生。
行为：必须记录签发来源与派生链；Provenance 与所属、系统身份权限分离；不可被普通运行态
      改写。
验收：可追溯谁签发、何时、从谁派生；普通运行态不能改写。
缺口：Provenance 存储与签名。

[SPEC-ID-005] 状态：共识｜模态：必须
条件：Agent 代表他人/组织行动。
行为：必须使用可转授、可撤销的 Delegation；必须声明可代表谁、有效期、是否可撤销。
验收：委托链可验证；撤销后失效；过期后失效。
缺口：委托链验证与撤销列表。

[SPEC-ID-006] 状态：共识｜模态：必须
条件：描述身份域结构。
行为：必须三层分离——所属=谁拥有；Provenance=谁签发/派生；系统身份权限=系统授予的
      可行动范围；三者独立字段，互不替代。
验收：三层可分别读取与验证；任一层缺失时对应判断失败而非静默降级。
缺口：三层字段 schema。

[SPEC-ID-007] 状态：共识｜模态：必须
条件：Agent 需要行动授权。
行为：必须由系统身份权限授予可行动范围；不得由 Agent 自述权限替代；与活生物信息共同
      构成授权。
验收：无系统身份权限时不能行动；权限范围可追溯签发方。
缺口：系统身份权限模型。

[SPEC-ID-008] 状态：共识｜模态：必须
条件：需要生物授权。
行为：活生物信息必须作为可验证授权因子，与系统身份权限叠加；不得以静态模板或设备级
      留存替代。
验收：静态指纹模板不能单独完成授权；活体校验失败时拒绝。
缺口：生物源与活体检测。

[SPEC-ID-009] 状态：共识｜模态：必须
条件：终端执行生物验证。
行为：生物比对必须以 Agent Core 内比对为主；终端只起辅助计算作用，可提供识别但不作
      最终结论；Agent Core 载体可自带生物识别。
验收：终端伪造 match 不能单独完成鉴权；Agent Core 内比对失败时拒绝实例化。
缺口：终端辅助比例。

[SPEC-ID-010] 状态：共识｜模态：不得
条件：任何授权、身份、主体化数据。
行为：不得在设备级持久留存；设备不得成为信任根；拔掉 Agent Core 后终端不得保留授权
      与主体化数据。
验收：设备存储中无授权令牌、无主体化数据；拔掉后不可用。
缺口：临时内存态清理。

[SPEC-ID-011] 状态：共识｜模态：必须
条件：Agent Core 存储数据。
行为：必须按敏感度分区——P0 公开、P1 内部只读、P2 私密读写、P3 机密、P4 禁止导出；
      每级解锁条件不同。
验收：低等级解锁不能读高等级分区；P4 不可导出。
缺口：P0–P4 解锁条件。

[SPEC-ID-012] 状态：共识｜模态：必须
条件：Agent 执行受保护操作。
行为：授权必须同时具备可验证的活生物信息与系统身份权限；缺一不可；不得以单要素替代。
验收：仅生物或仅权限时操作被拒绝；双要素齐备时可执行。
缺口：双要素组合策略。

================================================================================
3.7 系统数据 / 合法信息
================================================================================

[SPEC-DATA-001] 状态：共识｜模态：必须
条件：描述系统数据。
行为：系统数据必须是尚未处理或已经被处理进全局状态量子的信息实例；来源可以是
      Agent Core、Mobile Suite、成员权限协议。
验收：系统数据可按来源与处理状态分类；不得等同于 Valid Space。
缺口：系统数据来源分类。

[SPEC-DATA-002] 状态：共识｜模态：必须
条件：描述合法信息。
行为：合法信息必须由 Protocol 规定为合法；是构成 Valid Space 的元素。
验收：合法/非法可按 Protocol 规则判定；非法信息不进入 Valid Space。
缺口：合法信息判定规则。

[SPEC-DATA-003] 状态：共识｜模态：必须
条件：区分系统数据与合法信息。
行为：二者必须视为不同维度——系统数据是具体数据实例/来源；合法信息是 Protocol 合法性
      分类；不得简单合并或互为子集。
验收：同一数据可既是系统数据又是合法信息；也可为系统数据但非法；分类维度可分别查询。
缺口：交叉分类表。

[SPEC-DATA-004] 状态：共识｜模态：不得
条件：Agent Core 存储。
行为：系统数据不得默认落 Agent Core；只有明确归入主体化数据的部分才进 Agent Core。
验收：Agent Core 内容清单中系统数据默认不出现；例外需显式声明。
缺口：系统数据落 Agent Core 例外清单。

================================================================================
3.8 退相干清理
================================================================================

[SPEC-CLEAN-001] 状态：共识｜模态：必须
条件：拔掉 Agent Core。
行为：退相干必须即时生效——不再调度、不再发起请求、运行态不存在；不得等待任何清理
      动作才停止行为。
验收：拔掉后无新请求发起；无 loop 调度；退相干状态可观测。
缺口：无。

[SPEC-CLEAN-003] 状态：共识｜模态：可以
条件：不同场景需要不同清理策略。
行为：可在 Mobile Suite 中配置清理策略选项；选项至少包括“退相干后仅失效”与“退相干后
      彻底删除临时内存副本”；彻底删除不绑定“手动停内存”这一具体动作；可配置不等于
      可取消退相干即时性。
验收：策略选项可读可切换；彻底删除选项存在且可执行；退相干即时性不被关闭。
缺口：默认清理策略与切换权限。

[SPEC-CLEAN-004] 状态：共识｜模态：可以
条件：快速行动、一次性任务、紧急停止、长期驻留等场景。
行为：可按场景选择清理策略——快速行动/一次性任务/紧急停止优先退相干即时生效；
      需要彻底删除时选择彻底删除选项；不要求“手动停内存”作为必要步骤。
验收：场景与策略映射可配置；紧急停止时退相干即时生效；彻底删除可按策略执行。
缺口：清理场景清单。

--------------------------------------------------------------------------------
4. 生命周期与状态转换
--------------------------------------------------------------------------------
4.1 未插入 Agent Core
    → 终端 Mobile Suite 可独立存在；Embody 不实例化；无 agent 进行时。
4.2 插入 Agent Core
    → 鉴权中。
4.3 生物验证通过 + 三源可汇合
    → 实例化运行中；agent loop 启动；agent 进行时形成。
4.4 生物验证失败或三源不可汇合
    → 拒绝实例化或降级；记录失败原因。
4.5 实例化运行中发起远程请求
    → 目标 Mobile Suite 双校验；合法执行并留请求日志；非法拒绝并留请求日志。
4.6 拔掉 Agent Core
    → 运行态即时消失；退相干；运行时会话不存在；会话信息留存 Agent Core。
4.7 退相干后
    → 按清理策略选择仅失效或彻底删除临时内存副本；不要求手动停内存作为必要步骤。
4.8 重新插入 Agent Core
    → 可读取上次会话信息；重新鉴权；重新实例化。

6. 非目标与废弃项
--------------------------------------------------------------------------------
6.1 不设中心内核。
6.2 不使用 Carrier 作为节点抽象；由 Mobile Suite 承担。
6.3 不使用数据中枢作为全局存储组件；驿站机制仅作为内存中短暂坍缩处理节点。
6.4 不做设备绑定 / 设备级信任根；授权由活生物信息 + 系统身份权限构成，不落设备级。
6.5 不把“手动停内存”作为必要机制；彻底删除是清理策略选项。
6.6 不把 Harness 作为终端具身系统名称；统一称 Embody。
6.7 不把 Agent Core 简写为 Core。
6.8 不把 Valid Space 表述为“状态写入空间”；全局状态量子是 Valid Space 中的一个点。
6.9 不在本侧托管模型权重；模型参数默认不传输。
6.10 本预览不包含硬件、商业、联赛/市场/文创、训练闭环、论文写作。
